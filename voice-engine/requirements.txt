# --- TTS (Coqui XTTS-v2) ---
# Use the maintained community fork (importable as `TTS`, same XTTS code paths).
# The original `TTS` 0.22.0 is unmaintained and pins pandas<2.0, which conflicts
# with pandas>=2.0 below. coqui-tts allows pandas 2.x and Python 3.11/3.12, and
# matches the version running in voice-engine/.venv (coqui-tts 0.27.5).
coqui-tts>=0.27.5,<0.28
# transformers MUST stay on the 4.x line. coqui-tts declares only
# `transformers>=4.57` with no upper bound, so pip resolves to 5.x, which
# removed `isin_mps_friendly` from transformers.pytorch_utils — imported by
# TTS/tts/layers/tortoise/autoregressive.py:12. Without this cap, XTTS fails to
# load at runtime ("Warm-up of 'tts_service' failed") and there is NO voice
# output, while the container still reports healthy. Verified: 4.57.6 defines
# the symbol and satisfies coqui-tts's floor.
transformers>=4.57,<5
# Upper bound mirrors the pin in the Dockerfile (which installs these from the
# CPU wheel index BEFORE this file is processed). torch >= 2.9 makes coqui-tts
# demand the separate `torchcodec` package and XTTS fails to load without it.
# Keeping the cap here means a plain `pip install -r requirements.txt` outside
# Docker can't silently reintroduce the same breakage.
torch>=2.2,<2.9
torchaudio>=2.2,<2.9
soundfile>=0.12
librosa>=0.10
numpy>=1.22
